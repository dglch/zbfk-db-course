Зв'язки між таблицями (JOIN)

Концепція

Чому одного лічильника голосів мало

Колонка votes знає лише число. Але застосунку важливо знати, хто, за кого і коли проголосував.

На які питання лічильник не відповість

  • 🙋 Хто голосував? Число 15 не підкаже, хто саме підтримав студентку.
  • 📅 Коли? Без дати не порахувати голоси за конкретний тиждень.
  • 🚫 Чи чесно? Не видно, чи не натиснула одна людина «+1» п'ятдесят разів.

Обмеження

Зовнішній ключ: FOREIGN KEY

Колонка, яка посилається на первинний ключ іншої таблиці. СУБД стежить, щоб такі посилання завжди вели на справжні рядки.

Шаблон 
колонка INTEGER NOT NULL REFERENCES таблиця(id)
REFERENCES students(id) читається як «посилається на колонку id таблиці students». Тип колонки — INTEGER, як і в id (SERIAL — це INTEGER з лічильником).

Від чого захищає

  • 1 Голос «у нікуди». Не можна додати голос за студента з id = 99, якого немає в таблиці.
  • 2 Осиротілі голоси. Не можна видалити студента, за якого вже є голоси.
  • 3 Видалення таблиці. Не можна видалити students, поки на неї посилається інша таблиця.

💡 Таблиця, на яку посилаються (students), — батьківська. Таблиця з посиланнями (student_votes) — дочірня.

Об'єднання таблиць

JOIN: збираємо дані з двох таблиць

У журналі голосів є лише номер студента. Щоб побачити його ПІБ, «склеюємо» рядки двох таблиць за спільним ключем.

Шаблон 
SELECT таблиця_1.колонка, таблиця_2.колонка
FROM дочірня_таблиця
JOIN батьківська_таблиця
    ON батьківська_таблиця.id = дочірня_таблиця.зовнішній_ключ;
Скорочення: таблицям можна дати короткі імена — FROM student_votes v JOIN students s ON s.id = v.student_id. Тоді пишемо s.full_name замість students.full_name.

Як читати запит

  • ON Правило склеювання: рядки з'єднуються, коли student_id голосу дорівнює id студента.
  • T.C таблиця.колонка — так СУБД знає, з якої таблиці брати колонку. Обов'язково, якщо назва є в обох (як id).
  • JN JOIN (він же INNER JOIN) показує лише пари, що збіглися. Студенти без жодного голосу в результат не потраплять.
Об'єднання таблиць

LEFT JOIN: нікого не загубити

Показує усі рядки першої (лівої) таблиці. Якщо пари немає — на місці даних другої таблиці буде NULL.

Приклад: студенти та їхні номінації 
SELECT students.full_name, nominations.title
FROM students
LEFT JOIN nominations
    ON students.id = nominations.student_id
ORDER BY students.id, nominations.id;
Хто без пари? Додайте WHERE nominations.id IS NULL — і залишаться лише студенти, у яких немає жодної номінації.

Живий зразок коду

Зразок: таблиця номінацій

Студент тижня може отримати кілька номінацій. Вставте під стартовим скриптом і запустіть.

демо-скрипт (після стартового) 
CREATE TABLE nominations (
    id SERIAL PRIMARY KEY,
    student_id INTEGER NOT NULL REFERENCES students(id),   -- зовнішній ключ
    title TEXT NOT NULL                                     -- назва номінації
);

INSERT INTO nominations (student_id, title) VALUES
    (1, 'Найкращий науковець'),
    (4, 'Спортсменка року'),
    (4, 'Душа компанії');

-- Хто отримав яку номінацію
SELECT students.full_name, nominations.title
FROM nominations
JOIN students ON students.id = nominations.student_id;

🔍 Результат — 3 рядки: Олександр Коваленко — «Найкращий науковець», Софія Ткаченко — дві номінації.

Журнал голосів і запити з JOIN

Пишіть код під стартовим скриптом. Демо-таблицю номінацій у звіт не додавайте.

Крок 1 • таблиця 🏆 Студент тижня

Створіть student_votes

  • id — SERIAL PRIMARY KEY
  • student_id — INTEGER NOT NULL, зовнішній ключ на students(id)
  • voter_name — TEXT NOT NULL (хто голосував)
  • voted_at — DATE NOT NULL (дата голосу)

Крок 2. Додайте щонайменше 10 голосів за 4–5 різних студентів, дати — з '2026-09-08' по '2026-09-12'. За кількох студентів не голосуйте зовсім.

Крок 3 • 5 запитів
  1. Хто за кого голосував: ПІБ студента, ім'я того, хто голосував, і дата.
  2. Голоси лише за студентів групи М-21 (JOIN + WHERE).
  3. 5 найновіших голосів (ORDER BY + LIMIT).
  4. Усі студенти та їхні голоси, включно з тими, за кого не голосували (LEFT JOIN).
  5. Студенти, за яких ще ніхто не голосував.
Перевірте захист: після скріншотів спробуйте додати голос з student_id = 99 — СУБД має відмовити. У звіт цей код не додавайте.
