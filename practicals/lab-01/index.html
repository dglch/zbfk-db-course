Концепція даних

Що таке реляційна модель даних?

У реляційній базі вся інформація зберігається в таблицях. Кожна таблиця описує один вид об'єктів.

Анатомія реляційної таблиці

  • 📊 Таблиця (Table) — дані про однотипні об'єкти. У «Студенті тижня» це, наприклад, усі учасники голосування.
  • ⬇️ Стовпчик (Column / Поле) — одна властивість об'єкта: ПІБ, група, кількість голосів. Кожен стовпчик має свій тип даних.
  • ➡️ Рядок (Row / Запис) — один конкретний об'єкт: студентка Анастасія Мельник з групи Б-11.
  • 🔑 Первинний ключ (Primary Key) — стовпчик (зазвичай id), значення якого ніколи не повторюється. Навіть двох студентів з однаковим ПІБ не сплутати.
Чому «реляційна»? Реляційною база даних називається тому, що її дані зберігаються у вигляді таблиць, між якими встановлюються зв’язки (від англ. relation – відношення).
Приклад: таблиця students 3 записи
id PKSERIAL full_nameTEXT group_nameTEXT votesINTEGER
1 Олександр Коваленко М-21 12
2 Анастасія Мельник Б-11 9
3 Дмитро Бондаренко М-32 5

💡 У кожному стовпчику — значення одного типу: у votes лише цілі числа, у full_name лише текст. Саме таку таблицю ви створите в цій практичній.

Типізація SQL

Основні типи даних у SQL

Створюючи стовпчик, ми пояснюємо СУБД, які дані там зберігатимуться. Тоді вона не дозволить записати текст у поле для чисел.

Тип даних Що зберігає Приклади значень Де знадобиться у «Студенті тижня»
INTEGER Цілі числа без дробової частини 0, 12, 150 Кількість голосів votes
SERIAL Ціле число, яке СУБД заповнює сама: 1, 2, 3… (лічильник PostgreSQL) не вказуємо, СУБД додасть сама Номер запису id
TEXT Текст будь-якої довжини 'Анастасія Мельник', 'М-21' ПІБ, група, email, досягнення
REAL Дробові числа (з десятковою крапкою) 4.75, 10.5 Середній бал, відсоток голосів
BOOLEAN Логічне значення: так / ні TRUE або FALSE Чи бере студент участь у голосуванні?
DATE Календарна дата у форматі РРРР-ММ-ДД '2026-09-01' Дата реєстрації, початок тижня голосування
Правило лапок: текст і дати — завжди в одинарних лапках: 'М-21', '2026-09-01'. Числа і TRUE / FALSE пишуться без лапок. Подвійні лапки "…" у PostgreSQL означають назву стовпчика, а не текст.
Синтаксис DDL

Команда CREATE TABLE та обмеження (Constraints)

CREATE TABLE задає структуру нової таблиці. Обмеження — це правила, які захищають таблицю від невірних даних або даних, що не відповідають вимогам.

Шаблон синтаксису 
CREATE TABLE назва_таблиці (
    колонка_1 SERIAL PRIMARY KEY,
    колонка_2 TEXT NOT NULL,
    колонка_3 TEXT UNIQUE,
    колонка_4 INTEGER DEFAULT 0
);
Колонки розділяються комами ,. Після останньої колонки перед ) кома не ставиться. Команда закінчується крапкою з комою ;.

Ключові обмеження (Constraints)

  • PK PRIMARY KEY — первинний ключ. Значення унікальне і не може бути порожнім (як номер студентського квитка).
  • SR SERIAL — автонумерація 1, 2, 3… Разом з PRIMARY KEY дає ідеальний id: його не треба вигадувати самому.
  • NN NOT NULL — поле обов'язкове, порожнім залишити не можна.
  • UQ UNIQUE — повтори заборонені: два студенти не можуть мати однаковий email.
  • DF DEFAULT <значення> — значення за замовчуванням, якщо при додаванні рядка його не вказали (новий учасник має 0 голосів).
Живий зразок коду

Зразок: таблиця тижнів голосування

Застосунку треба знати дати кожного тижня конкурсу. Скопіюйте скрипт у PlayCode, запустіть і відкрийте вкладку Database.

демо-скрипт: voting_weeks 
-- Прибираємо стару версію таблиці, щоб скрипт можна було запускати повторно
DROP TABLE IF EXISTS voting_weeks;

CREATE TABLE voting_weeks (
    id SERIAL PRIMARY KEY,            -- номер тижня, СУБД рахує сама
    title TEXT NOT NULL,              -- назва: 'Тиждень 1'
    start_date DATE NOT NULL,         -- початок голосування
    end_date DATE NOT NULL,           -- кінець голосування
    prize TEXT DEFAULT 'Грамота',     -- нагорода переможцю
    is_open BOOLEAN DEFAULT TRUE      -- чи можна зараз голосувати
);

🔍 У вкладці Database з'явиться таблиця voting_weeks з 6 колонками. Біля id стоїть позначка PK, а тип показано як INTEGER: SERIAL — це INTEGER з автоматичним лічильником.

Типові помилки

Червоне повідомлення? Розшифровуємо

Помилка — це не катастрофа: СУБД просто відмовилася виконувати команду і нічого не зіпсувала. Текст помилки в Console підказує, де шукати проблему.

Повідомлення PostgreSQL Що сталося Як виправити
relation "students" already exists Таблиця вже створена під час попереднього запуску Почніть скрипт з DROP TABLE IF EXISTS students;
syntax error at or near ")" Зайва кома після останньої колонки Приберіть кому перед )
syntax error at or near "group_name" Пропущена кома перед названою колонкою Поставте кому в кінці попереднього рядка
type "integr" does not exist Помилка в назві типу даних Перевірте написання: INTEGER, TEXT, DATE…
column "is_active" is of type boolean but default expression is of type integer DEFAULT 1 для логічного поля Пишіть DEFAULT TRUE або DEFAULT FALSE
column "email" specified more than once Дві колонки з однаковою назвою Перейменуйте або видаліть зайву
DROP TABLE видаляє таблицю разом з усіма даними. У навчальному скрипті це зручно: кожен запуск будує таблицю з нуля. На справжньому сервері так не роблять.

Завдання 🏆 Студент тижня

Таблиця students

  • id — SERIAL PRIMARY KEY
  • full_name — TEXT NOT NULL (ПІБ)
  • group_name — TEXT NOT NULL (група, напр. 'М-21')
  • email — TEXT UNIQUE (пошта для входу)
  • achievements — TEXT (за що номінують)
  • votes — INTEGER DEFAULT 0 (кількість голосів)
  • is_active — BOOLEAN DEFAULT TRUE (бере участь)
  • registered_at — DATE NOT NULL (дата реєстрації)

Порядок виконання

  • Угорі скрипту — коментар з ПІБ і групою (зразок на наступному слайді).
  • Рядок DROP TABLE IF EXISTS students;, далі ваш CREATE TABLE students (…);
  • Запустіть код (Run) і переконайтеся, що в Console немає помилок.
  • Відкрийте вкладку Database → таблиця students у списку TABLES.
Перевірте себе: у блоці STRUCTURE має бути 8 колонок, позначка PK біля id і правильні типи. SERIAL там показано як INTEGER — так і має бути.
