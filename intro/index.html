Два типи пам'яті: Де живуть ваші дані?

Перед тим як говорити про бази даних, згадаймо, як процесор комп'ютера взагалі працює з інформацією.

1. Енергозалежна пам'ять (RAM / ОЗУ)

Очищується при вимкненні живлення

Швидкий робочий простір процесора, де знаходяться відкриті вкладки браузера, запущені програми та змінні поточних обчислень.

  • Швидкість: Блискавична (наносекунди). Процесор миттєво зчитує та змінює змінні.
  • Вразливість: Зникає живлення чи падає програма — все очищується в нуль.
  • Метафора: Клейкі стікери біля клавіатури. Ідеально для швидких робочих поміток «тут і зараз». Але вони легко губляться і не підходять для довготривалого зберігання інформації.

2. Енергонезалежна пам'ять (Storage / Диск)

Зберігає дані без електричного струму

Фізичні носії: SSD-накопичувачі, NVMe, жорсткі диски (HDD), флеш-пам'ять.

  • Надійність: Записані байти зберігаються роками, навіть коли сервер вимкнено з розетки.
  • Швидкість: Повільніша за оперативну пам'ять у 100–1000 разів (мікросекунди / мілісекунди).
  • Метафора: Друкована книга або записник у сейфі. Потрібен час, щоб записати, зате надійно назавжди.
Ключова дилема програміста: Як поєднати космічну швидкість обробки інформації в ОЗУ з абсолютною надійністю збереження на диску?

Чому це здається гарною ідеєю?

  • Простота реалізації: Створили список у коді — і все працює за 5 хвилин.
  • Миттєва швидкість: Зчитування з ОЗУ відбувається за частки мікросекунди.
  • Нуль налаштувань: Не потрібно встановлювати та адмініструвати жоден сервер БД.

А що станеться у реальному житті?

Сервери у клауді чи в серверній кімнаті — це звичайні комп'ютери. Що трапиться, якщо:

Проміжне рішення Файлова система

«А чому б просто не записувати у файл students.txt чи data.json?»

Перша здорова думка кожного студента: якщо диск енергонезалежний, давайте просто скидати все у звичайний файл!

💥

1. Стан гонитви (Race Condition)

Що буде, якщо 100 користувачів одночасно натиснуть «Голосувати»?

Файл не можна одночасно безпечно відкривати на запис 100 процесами. Останній запис перезапише всі попередні, і 99 попередніх голосів просто зникнуть, або файл взагалі заблокується операційною системою з помилкою.

🐢

2. Катастрофічна швидкість

Якщо в коледжі декілька тисяч студентів, файл `data.json` буде важити десятки мегабайт.

Щоб знайти топ-10 лідерів чи профіль одного студента, серверу доведеться щосекунди зчитувати з диска та парсити гігантський текстовий файл від початку до кінця. Сервер просто може зависнути від такого навантаження.

💔

3. Пошкодження даних (Corruption)

Сервер якраз записував у файл новий голос... і саме в цю мілісекунду стався збій.

Результат: файл обірвався на півслові `{"votes": 4`. Тепер це невалідний JSON, весь файл пошкоджено, і при наступному старті сайт видасть фатальну помилку для всіх користувачів.

Висновок: Звичайні файли чудово підходять для зображень чи конфігурацій, але абсолютно непридатні для динамічних багатокористувацьких веб-сервісів!
Порятунок Правильна інженерія

Знайомтесь: База Даних (БД) та СУБД

Спеціалізований софт, над створенням якого інженери та науковці працювали останні 50 років.

🗄️

База Даних (БД)

Самі структуровані дані.

Це організована таблична інформація: профілі студентів, відділення коледжу, історія голосів, часові мітки та зв'язки між ними.

🛡️

СУБД (DBMS)

Система Управління Базами Даних.

Спеціальна високооптимізована програма (сервер), яка керує читанням, безпечним записом на диск, пам'яттю та блокуваннями (PostgreSQL, MySQL, SQLite).

💬

Мова SQL

Structured Query Language.

Універсальна стандартизована мова запитів, якою людина або веб-сервер спілкується з СУБД: SELECT * FROM students
ORDER BY votes DESC;

🏛️
Проста аналогія: «Банківське сховище»

БД — це гроші та сейфи з рахунками клієнтів.
СУБД — це охорона, броньовані двері та персонал банку, який нікому не дозволяє вкрасти гроші чи отримати дані вашого рахунку.
SQL — це офіційний бланк заяви, за яким ви звертаєтесь до банку («Видати залишок по рахунку #42»).

Переваги Чому це працює

Суперсили СУБД: Які проблеми вона вирішує

Чому жоден серйозний сервіс (Instagram, Uber, Дія, Amazon) не існує без СУБД.

🛡️

1. Гарантована персистентність (ACID / WAL)

Write-Ahead Logging

СУБД використовує журнал транзакцій. Перш ніж підтвердити клієнту успіх, запис фіксується в журналі на диску. Якщо в наступну наносекунду з сервером щось станеться — після рестарту СУБД автоматично відновить всі дані до останнього біта.

⚡️

2. Паралельний доступ (Concurrency)

Тисячі запитів на секунду

СУБД знає, як блокувати окремі рядки таблиці, а не всю базу. Якщо 1000 людей одночасно голосують за різних студентів, СУБД паралельно оновлює їхні лічильники без жодних конфліктів та перезаписів.

🚀

3. Індекси та блискавичний пошук

Швидкість O(log N) замість O(N)

Як предметний покажчик у кінці енциклопедії. СУБД не сканує мільйон студентів по черзі: за допомогою спеціальних структур даних (B-Tree індексів) вона знаходить потрібного студента за 0.001 секунди.

🔐

4. Цілісність, безпека та зв'язки

Реляційні обмеження

Неможливо віддати голос за студента, якого не існує. Неможливо створити студента з негативною кількістю голосів. СУБД автоматично контролює правила валідації на рівні ядра системи.

За що відповідає Frontend?

Показати кнопки, фотографії студентів, форму голосування та гарний дизайн користувачеві.

За що відповідає Backend?

Перевірити, чи має право користувач голосувати (авторизація), захистити від накрутки голосів та сформувати SQL запит.

За що відповідає СУБД?

Надійно зберегти дані, забезпечити одночасний доступ мільйонів користувачів та миттєво віддати лідерборд.

Навчальний план Практичні навички

Дорожня карта нашого курсу: 6 практичних занять

Практична 01

Знайомство з СУБД та перша таблиця

Реляційна модель. Типи даних. Первинний ключ. Створюємо таблицю студентів за допомогою команди CREATE TABLE.

Практична 02

Вставка та вибірка даних з фільтрацією

Команди INSERT, SELECT, WHERE. Наповнюємо таблицю студентів і шукаємо записи за умовою.

Практична 03

Зміна, сортування та обмеження даних

Команди UPDATE, DELETE, сортування ORDER BY та обмеження LIMIT. Знаходимо топ-лідерів рейтингу.

Практична 04

Зв'язки між таблицями (JOIN)

Реляційна модель: як розділити студентів та голосування. Зовнішні ключі (FOREIGN KEY) та об'єднання даних за допомогою JOIN.

Практична 05

Агрегація даних та бізнес-аналітика

Функції COUNT, SUM, AVG, групування GROUP BY. Рахуємо статистику: яка група набрала найбільше голосів.

💡 Що ми дізналися сьогодні:

  • ОЗУ швидка, але ненадійна: Будь-який збій або перезапуск стирає все безповоротно.
  • Звичайні файли — пастка для вебу: Вони ламаються при одночасному доступі та гальмують на великих обсягах.
  • СУБД гарантує персистентність: Навіть коли сервер падає, дані залишаються неушкодженими.
  • SQL — мова успіху: Знаючи базовий SQL, ви можете діставати аналітику з будь-якої корпоративної системи.
